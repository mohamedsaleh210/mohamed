# سند v15 — وثيقة المعمارية والنواة المتكاملة

## القرار التنفيذي

- تبنى النسخة الجديدة فوق وظائف v14.2 ولا تحذف أي بيانات أو وحدة قائمة.
- قاعدة التشغيل النهائية PostgreSQL مشتركة، وكل سجل تشغيلي يحمل `tenant_id` مع عزل على مستوى قاعدة البيانات عبر RLS.
- يظل ملف v14.2 الأصلي دون تعديل، ويجري العمل داخل نسخة مستقلة ثم يتم الاستبدال بعد نجاح الاختبارات والترحيل التجريبي.
- أول تسليم قابل للتجربة هو مسار رأسي واحد يربط: مالك سند ← المكتب ← العميل، ببيانات تجريبية مترابطة.
- العربية والإنجليزية متساويتان وظيفيًا، مع قوالب دولة مستقلة تبدأ بمصر والسعودية.

## النواة المرئية الأولى

1. واجهة عامة بهوية المرجع المعتمد: كحلي/بترولي عميق، ذهبي دافئ، عاجي وأبيض، وصور واقعية ممزوجة بمعاينات النظام.
2. صفحة رئيسية هادئة المساحات تضم البحث الموحد، المؤشرات، الجمهور، المكاتب، الخدمات الأكثر طلبًا، رحلة العمل، الباقات، الآراء، الأسئلة الشائعة والدعوة النهائية.
3. مركز محتوى يتحكم في إظهار الأقسام وترتيبها بالسحب والنصوص والصور والروابط والمؤشرات والباقات والآراء والأسئلة الشائعة.
4. رحلة عميل من صفحة الخدمة إلى فحص الأهلية وطلب كزائر ثم حساب وتتبع وعرض سعر وموافقة ودفعة مقدمة.
5. لوحة مكتب تستقبل الطلب وتراجع النواقص وتعد عرض السعر وتعيّن الفريق والمهام وتحدّث ما يراه العميل.
6. لوحة مالك سند تدير المكاتب والباقات والتجارب والخدمات المركزية والعمولات وسياسة الإسناد ومحتوى الواجهة.

## حدود الملكية والعزل

| النوع | المالك | العزل |
|---|---|---|
| الدول والعملات وقوالب الدولة | مالك سند | مركزي |
| الخدمات المركزية وإصداراتها | مالك سند | مقروءة للمكاتب المسموح لها |
| الخدمات الخاصة | المكتب | داخل `tenant_id` فقط |
| العملاء والطلبات والمستندات والماليات | المكتب المنفذ | داخل `tenant_id` فقط |
| الباقات والاشتراكات والعمولات والتحويلات | مالك سند | مركزي مع عرض الحصة اللازمة للمكتب |
| سجل التدقيق | النظام | غير قابل للتعديل أو الحذف من الواجهة |

## دورة الطلب في النواة

`مسودة زائر → مرسل → مراجعة أولية → نواقص/مكتمل → إعداد عرض → انتظار العميل → مقبول → انتظار المقدم → قيد التنفيذ → مكتمل → مغلق`

الفروع الإضافية: رفض العرض، طلب تعديل، إلغاء، استرجاع، نزاع، تعليق، وتظلم. كل انتقال يسجل المنفذ والوقت والسبب والقيمة السابقة والجديدة.

## استراتيجية الترحيل

1. قراءة SQLite في وضع read-only وإنشاء تقرير بعدد الصفوف ومفاتيح العلاقات.
2. إنشاء مكتب أساسي يمثل بيانات v14.2 الحالية.
3. نقل الجداول المرجعية أولًا، ثم المستخدمين والعملاء والشركات والفروع، ثم الطلبات والعلاقات، ثم المستندات والماليات والسجلات.
4. الاحتفاظ بالمعرف القديم في `legacy_id` لكل كيان قابل للتتبع.
5. نسخ الملفات مع بصمة SHA-256 ومقارنة العدد والحجم.
6. إعادة حساب الإجماليات المالية من الحركات، لا نسخ الأرصدة وحدها.
7. تشغيل مقارنة قبل/بعد: العدد، المجاميع، العلاقات اليتيمة، آخر المواعيد، وحالات الطلبات.
8. تنفيذ ترحيل تجريبي كامل ثم ترحيل نهائي وقت الإطلاق، مع منع الكتابة في النسخة القديمة أثناء نافذة القطع.

## معايير قبول أول نسخة

- لا يستطيع مستخدم مكتب قراءة سجل مكتب آخر حتى عبر رابط مباشر أو استعلام معدل.
- يستطيع مالك سند إنشاء مكتب وباقة وخدمة مركزية وتحديد السياسة والعمولة والظهور.
- يستطيع المكتب تهيئة هويته وخدماته وموظفيه ثم استلام طلب وإصدار عرض سعر.
- يستطيع العميل إنشاء طلب كزائر، إنشاء حساب عند الإرسال، استكمال النواقص، قبول العرض ودفع المقدم التجريبي.
- كل عنصر ظاهر في الرئيسية له مصدر إدارة واضح، ولا توجد أرقام أو آراء أو أسئلة ثابتة داخل القالب.
- جميع الشاشات الأساسية تعمل RTL/LTR وعلى الهاتف، مع لوحة ألوان المرجع المعتمد.
- اختبارات الصلاحيات والعزل والماليات والهجرة والأمان تنجح قبل الاستبدال المباشر.

## ما لا يعد «مكتملًا» بمجرد وجود واجهة

- بوابة الدفع لا تعد حية قبل حساب تاجر ومفاتيح وبيئة اختبار معتمدة.
- الفوترة الإلكترونية لا تعد حية قبل اعتماد الدولة وشهاداتها ومفاتيحها.
- واتساب وSMS والتوقيع والتخزين السحابي تحتاج حسابات رسمية ومفاتيح منفصلة لكل بيئة.
- الذكاء الاصطناعي لا يرسل رأيًا أو مستندًا للعميل دون مراجعة بشرية، ويسجل المصدر والمدخل والمخرج والتعديل.
